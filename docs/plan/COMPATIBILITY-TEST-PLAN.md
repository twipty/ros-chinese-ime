# 兼容性与可用性测试计划

> 状态：**计划已制定，尚未执行**（2026-11-27）。
> 目的：把「较新软件兼容性」从推断变成有证据的结论，明确本项目**在哪里可用、在哪里不可用、为什么**。
> 边界：本计划不改变产品代码、不扩大平台白名单、不新增支持承诺；结论只入档，是否改动产品由 owner 另立轮次决定。

## 0. 为什么需要这份计划

当前证据覆盖面很窄，且三类空白性质不同，不能用同一句话回答「兼容性怎么样」：

| 空白 | 现状 | 性质 |
|---|---|---|
| 三方应用、浏览器、RichEdit | 只有记事本 EDIT 控件跑过 [M2 验收单](../milestones/m2/M2-ACCEPTANCE.md) 15/15；[ROADMAP §M7](../plan/ROADMAP.md) 把三方应用与 RichEdit 列为待办 | **未实测**，不是已知失败 |
| 组合串消息链 | ReactOS imm32 未实现 `ImmSetCompositionString`，无 `WM_IME_STARTCOMPOSITION` / `WM_IME_COMPOSITION`，组合串靠自绘（[HANDOVER §11.4](../handover/HANDOVER.md)） | **机制性缺口**，应用侧内联预编辑可能拿不到 |
| 64 位 / ARM64 / 真 Windows | 只有 i686 产物；上游 64 位无 WoW64 且 `offsetof` 断言在 64 位编译失败（[可移植性评估](../reviews/PORTABILITY-UPSTREAM-64BIT-ARM64.md)）；GUI 白名单只认 ReactOS（[Windows 评估](../reviews/WINDOWS-GUI-COMPATIBILITY-ASSESSMENT.md)） | **平台阻塞**，静态层面已明确 |

本计划用统一的用例 ID、判定等级和证据规范，把三者分开收口。

## 1. 判定口径

### 1.1 兼容性等级（每个「应用 × 平台」单元各判一次）

| 等级 | 含义 | 判据 |
|---|---|---|
| **C0 已验证** | 该组合下核心输入闭环通过 | 组合串出现 + 候选可选 + 上屏到应用文档，三项截图/日志齐备 |
| **C1 条件可用** | 能输入但有可见退化 | 例如上屏正常但候选窗不跟随、无应用内预编辑、需特定操作顺序 |
| **C2 不支持** | 实测有稳定复现的功能失效 | 有截图/日志，且排查后确认不是测试环境问题 |
| **C3 平台阻塞** | 环境本身不具备测试条件 | 应用不可得 / 系统架构不匹配 / 上游 API 缺失。**不计为产品缺陷** |

### 1.2 可用性等级（每个平台整体判一次）

| 等级 | 含义 |
|---|---|
| **U0 完整** | C 轴全部用例达 C0，无硬失败 |
| **U1 基本可用** | 记事本与至少一个非记事本控件达 C0/C1，无硬失败 |
| **U2 不可用** | 记事本基线回归未过，或出现硬失败 |

### 1.3 硬失败（出现任一立即停止该轮，不继续取证）

- 蓝屏 / 系统重启 / 关键用户进程崩溃；
- 词库或设置文件损坏、`/status` 由 OK 变 MISSING/MISMATCH；
- 输入上屏内容重复或丢失且可稳定复现（不是注入节奏问题）；
- 安装器报错后系统输入法列表出现孤儿项。

## 2. 环境与分工

### 2.1 三台 guest 的角色（不可互换）

| Profile | 磁盘 | 系统 | 入口 | 角色 |
|---|---|---|---|---|
| `6080` | `reactos.qcow2` | 0.4.16 clean | noVNC `6080` / VNC `5901` | 开发期探索与失败用例复现，**不作验收证据** |
| `6081` | `reactos-nightly.qcow2` | 0.4.17-dev-1398 | noVNC `6081` / VNC `5902` | 里程碑验收（nightly 侧） |
| `6082` | `reactos-stable.qcow2` | 0.4.16 正式 | noVNC `6082` / VNC `5903` | 里程碑验收（stable 侧） |

- 里程碑结论只认 **6081 + 6082 成对**；两者结果不一致时分别记录，不取平均、不挑一个。
- 启动：`bash m0/vm/start-vm.sh 6081`（6082 换号），guest 下载入口 `http://10.0.2.2:8000/`。
- 安装与版本判据沿用 [M4 guest 步骤 §1.1 / §3.1](../../m0/vm/evidence/M4-GUEST-VERIFY-STEPS.md)：装前核对 GUI `6cb328e5…`（3,629,278 B），重启后 `/status` 第一行须为 `995,029` 字节；词库须 `present (6530601 bytes)` 且 `lexicon sha a89ec5e5… (OK)`。哈希或字节数不符即中止本轮，先修部署。

### 2.2 分工纪律

- **guest 内所有键鼠操作由 owner 手工执行**。我不做键盘/鼠标注入（VNC、HMP sendkey、辅助点击程序一律不用）。
- 我负责：构建与部署、核对哈希、写操作步骤、用 HMP `screendump` 只读抓当前画面辅助判读、整理结果矩阵。
- `screendump` 抓帧属纯读取，可用来确认画面状态，**不能替代**操作过程截图作为用例证据。
- 失败回退：`copy /y` 报 `err=32` 或出现 `stale payload : …ime.old exists` 时，按 [HANDOVER §6.4.1](../handover/HANDOVER.md) 先切默认输入语言 / 重启 / 再跑一次安装，不要重复硬拷。

## 3. 测试矩阵

优先级：**P0** = 前置必过；**P1** = 回答「是否可用」的主证据；**P2** = 补充结论；**P3** = 时间允许时做。
每个用例都要记：实测现象、截图文件名、判定等级、失败时是否可稳定复现。

### 3.1 A 轴 — 平台与环境

| ID | 平台 | 操作 | 期望 / 结论口径 | 优先级 |
|---|---|---|---|---|
| A1 | 6082 stable 0.4.16 | 装 alpha0.1.2 GUI + 重启 + `/status` | 版本判据符合 §2.1；本轴作为 stable 基线 | P0 |
| A2 | 6081 nightly 0.4.17-dev | 同上 | 同上；与 A1 成对对照 | P0 |
| A3 | 6080 开发机 | 同上 | 先行试装，用于暴露安装/加载问题，不进验收结论 | P0 |
| A4 | 上游 AMD64 | 静态复核 64 位断言、构建路径、WoW64 前提 | 只更新静态评估结论；**不做实机实测**，输出 C3 | P2 |
| A5 | 上游 ARM64 | 跟踪 CORE-18200 是否有「用户态 Win32 应用可运行」证据 | 无证据即维持 C3，不启动实机 | P3 |
| A6 | 真 Windows | GUI 白名单不放行；仅 CLI `/step1..4` 诊断 | 输出 C3 + 理由；不宣称兼容 | P3 |

## 4. 执行顺序与门禁

| 阶段 | 内容 | 入口条件 | 出口条件 |
|---|---|---|---|
| **P0 前置冻结** | A1–A3、D1–D2 | 宿主构建完成、`m0/share/` 哈希核对一致 | 三台均 `/status` 达标；否则本轮不成立 |

## 5. 证据规范

- 目录：`m0/vm/evidence/compat/`，按阶段建子目录 `p0-setup/`、`p1-baseline/`、`p2-platform/`、`p3-apps/`、`p4-stability/`、`p5-font-uninstall/`。
- 截图命名：`<用例ID>-<机器>-<序号>.png`，例：`B2-6081-01.png`。
- 结果矩阵：每阶段一份 `result.md`，用 §6 模板；最终汇总 `m0/vm/evidence/compat/CONCLUSION.md`。
- 版本自证：每轮第一张截图必须是 `/status` 输出，证明装的是哪一版（[版本判据](../../m0/vm/evidence/M4-GUEST-VERIFY-STEPS.md) §3.1）。
- 日志：trace 版见 `C:\rospinyin-trace.log`，内核日志见 `m0/vm/rosdbg.log*`；日志只作辅助，不能替代截图。
- owner 回传截图时注明用例 ID 与机器号；缺任一项该用例判 **BLOCKED**，不判 PASS。
